The user explicitly requested additional sample shareholders with both Common and Preferred holdings for initial pilot purposes. Use fictional, clearly PILOT-labeled people and family lines, reserved example email addresses, and no SSNs.

**Why:** Pilot records must not be confused with actual company ownership or personal information. The earlier report examples remain format references, not data-import sources.

**How to apply:** Keep CLI fixture imports development-only and explicit. The user also authorized adding the original fictional dataset to the published pilot so participants can see it. Use an explicit, authenticated Settings import there—not startup/deployment seeding or wholesale database replacement. Preserve existing records, allocate new local certificate numbers, and prevent duplicate imports. Do not fabricate employee sign-offs, generate legal certificate PDFs, or send notifications for imported samples. Pilot holdings are included in normal totals and reports, so keep that limitation clear.

Use “Shareholder,” not “Stakeholder,” throughout the app and its report outputs.

**Why:** The user explicitly requested this terminology in all instances.

**How to apply:** Preserve this vocabulary in future visible copy, exports, and new report features.
