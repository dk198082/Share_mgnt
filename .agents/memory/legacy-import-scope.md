The user intends to populate Azure Production from the previous shareholder application and leave Replit production pilot data behind. They explicitly want step one of the migration process to remove existing application data so the import starts empty. The intended Settings import utility covers initial migration and controlled future reuse.

**Why:** The user distinguished the real legacy-system migration from the earlier pilot-data copy and asked for a recommended process first.

**How to apply:** Do not treat existing pilot records or sample reports as the authoritative migration source. Plan an empty application baseline, not a merge with pilot data. The request to revise step one is not an instruction to execute a reset immediately. Before deletion, explain the exact scope and confirm execution; prefer isolating the application's schema over dropping the potentially shared Azure database. Confirm legacy export structure and historical coverage before implementation.

## Azure-only real-data boundary

The user requires the import utility to execute in Azure and does not plan to load real data into Replit.

**Why:** Azure PostgreSQL as the destination alone does not prevent a Replit-hosted importer from receiving and processing real data.

**How to apply:** Develop and test with synthetic data in Replit. Request only fully anonymized examples or column definitions here. Run production import services, reset tooling, staging, and subsequent real-data application access in the approved Azure environment; store files in SharePoint. Do not route real workbooks, records, or reports through Replit. Verify hosting and isolation before execution; do not assume Azure hosting is already established.

## Review and execution gates

The user initially required a pause for mapping review, then authorized building the utility and explicitly confirmed anonymized sample files may seed Replit Preview. Production reset and production import each still require separate approval.

**Why:** The user wants to review how legacy records will be interpreted before those decisions become executable conversion behavior.

**How to apply:** Use fully anonymized examples for structural assessment/sample seeding and wholly synthetic isolated regression fixtures. Do not interpret the Preview build/load authorization or approval of mappings as authorization to delete records, import real data, or cut over production.

## Reduced-sample import scope

For anonymized Preview samples, use the supplied shareholder profiles and explicit technical-ID crosswalk to scope eligible certificates. Report broader raw securities as excluded; do not invent missing profiles or historical transfer events to make a reduced sample complete. Clearly label imported samples and preserve existing Preview records.

**Why:** The user confirmed reduced anonymized exports are sufficient to build and seed Preview, not a request for a complete anonymized company dataset.

**How to apply:** Reconcile selected certificates against matching ownership controls. Keep full-company production scope and identity exceptions as separately reviewed rules; a sample's unique External IDs do not prove every production External ID is unique.

## Destination-first mapping review

Review application tables/fields first, proposing a source mapping and explicitly distinguishing required source facts, optional blanks, and values generated by the utility. Include operational tables for completeness without asking the business to populate them from Pulley.

**Why:** The user clarified that reduced anonymized examples are for understanding field types/values, not a complete anonymized migration, and requested this simpler review before building the utility.

**How to apply:** Small representative samples and synthetic linked fixtures are enough for design and development. Do not require complete anonymized exports or company-wide reconciliation to finish the mapping. Full-source validation belongs to the final approved Azure migration, not this review gate.

## Three-table business review

Organize the primary mapping workbook around Shareholders, Certificates and Share_Transfers, with individual shareholder profile properties included on Shareholders. Summarize the other tables separately as configured, generated or not imported; keep the full technical inventory as a reference.

**Why:** The user explicitly chose to simplify the workbook around those three legacy-business tables, rather than review source mappings for operational/system tables.

**How to apply:** Do not confuse three source-mapped tables with only three tables receiving writes. Counters, truthful import provenance/history and verified historical PDF associations remain utility responsibilities; do not fabricate live approvals to accommodate old PDFs.

## Approved family-line source

Use the Pulley Shareholder Information export's `Comments` field as Family line, retaining the original notes as well. Preserve names as supplied rather than unifying different family labels; blank Comments may remain blank.

**Why:** After seeing Family line blank in the converted samples, the user explicitly selected “Use Comments as family line.” The earlier rule against this unconfirmed mapping is superseded.

**How to apply:** Apply this source mapping in future legacy imports and mapping-review documents. Do not infer family names from surnames or other fields, and do not silently truncate values beyond the field limit.

## Simple Azure import access

The user explicitly wants anyone with access to the Azure application to run the
import utility. No dedicated import role, Entra group assignment, additional
sign-in or import-specific activation is required. Keep real-data importing
blocked on Replit hosts, even when the database points at Azure.

**Why:** The user expects roughly four executive users and three IT users and
rejected the additional import-authorization layer as overcomplicated.

**How to apply:** Reuse ordinary application sign-in and normal Azure deployment
configuration. Preserve upload validation, review/confirmation, individual audit
attribution and optional IT pause controls. Simplifying access does not approve a
reset or production data load. Do not silently omit unresolved company securities.
